# Windows ↔ WebUI function audit

Source baseline: `windows/src/application.rs`, `windows/src/main.rs`, `windows/ui/app.slint`, and `windows/src/range.rs`. Browser implementation: `python/web_preview.py`, `python/web_preview/index.html`, `app.js`, and `app.css`. This is a rule and event-sequence audit, not a claim that the read-only browser template can perform Windows writes.

## Library identity, navigation, and status

| Function | Windows rule and event sequence | Browser state / remaining difference |
| --- | --- | --- |
| Fallback authority | `LibraryState::is_fallback_album` (`application.rs:739`) checks only whether `album_mbid.trim()` is empty. `fallback_album_rows` (`:1000`) uses that predicate. Compilation status and Album Artist do not grant fallback authority. Test `fallback_uses_missing_album_id_authority_and_honors_status_filters` (`:5758`) covers compilations with and without IDs. | `/api/albums?view=fallback` now uses the same missing-ID predicate. In the isolated index, **American Pie 2** and **Gold** both have IDs, so Fallback has zero rows. Regression test: `python/test_web_preview_fallback.py`. |
| Artist versus fallback scope | `album_is_in_active_review_view` (`application.rs:729`) keeps missing-ID albums in Fallback and MBID-backed albums in Artists. Artist overview fallback appearances are projected by matching track artist, not by treating a whole compilation as the artist's album (`:783`, `:809`, tests `:5223`, `:5492`). | Browser artist overview still reads the artist's indexed albums directly. Track-level fallback projection and associated status are **not yet implemented**; the test index has no usable track rows for this screen. |
| Selection focus | Windows `toggle_fallback_album_focus` (`application.rs:1280`) separates expanded fallback album focus from scan selection; `select_all_for_review` (`:1734`) selects pending tracks when a fallback album is expanded. Switching tabs clears stale focus (test `:5990`). | Browser navigation loads one artist or album, with request IDs discarding late responses. The browser has no scan queue or fallback track expansion yet. |
| Media status categories | `StatusFilter` and `all_status_filters` (`application.rs:38`, `:64`) define seven categories plus All. All seven are enabled initially. `toggle_status_filter` (`:1085`) toggles a category; All restores all. `status_count` (`:1103`) counts artists, albums, or fallback **tracks** according to view. `status_filter_color` (`main.rs:19725`) assigns category colors. Windows paints its enablement dot green/red and its label/count with the category color (`app.slint:629–636`). | Browser displays all categories, their current-index counts, and multi-select state. Per the WebUI request, the filter bullet and matching library-row bullet both use the same status color; fill versus outline shows selection. Artist `complete` maps to Artist Complete. Fallback counts are still album counts until track hydration exists; exact composite artist status requires the Windows aggregation rules. |
| Filter lock | `main.rs:8051` ignores status changes when the media lock is closed. `app.slint:618–636` disables text search, selection modes, and category toggles; lock retains prior choices. | Browser disables those controls when locked and retains the current choices. |
| Select modes | `select_all_for_review` (`application.rs:1734`) replaces selection with eligible albums in the active view; expanded fallback selects pending tracks. `select_filtered_for_review` (`:1798`) requires a text, status, or fallback scope and then selects visible eligible records. None clears selection (`:1567`). | Browser buttons now represent review selection in memory, with Filtered requiring a filter or Fallback view. They **do not create a scan queue**. Eligibility and track selection must be connected before LAUNCH can use this selection. |

## Sources and candidates

| Function | Windows rule and event sequence | Browser state / remaining difference |
| --- | --- | --- |
| Source cards | `candidate_source_card_names` (`application.rs:2467`) is config-driven. `apply_candidates` (`:4298`) updates counts/status. `set_source_enabled` (`:3528`) saves source enablement via `main.rs:8341`; order can change. Source selection can shortcut-filter visible candidates (`:3478`). | Browser has source cards and live counts, but only Local, Fanart.tv, and Deezer search images in this prototype; Navidrome supplies metadata. Other cards are pending. It must not claim those providers were searched. Config writes are unavailable. |
| Candidate admission | `CandidateState::matches_filter` (`application.rs:2050`) uses source, image type, policy, and source/projected resolution range. `Range::classify` (`range.rs:53`) defaults to 1200 / 1800 / 2400 / 3600 px boundaries. Windows artist-art local candidates (`main.rs:4818`) are explicitly acceptable even when small. | Browser categories and counts use current candidate metadata and the Windows default resolution thresholds. Artist local/online art is explicitly acceptable. The browser does not receive the Windows scanner's policy status, strict override, upscaled flag, or customized range settings; those classes can differ from Windows. |
| Initial candidate filter state | `activate_available_candidate_filters` (`application.rs:3373`) clears unlocked filters after a new result set and includes every category with a positive count; if locked, it retains current state. | Browser now auto-includes categories with results and preserves filters when locked. A new focus clears prior candidates and unlocked filter state. |
| Candidate tri-state | `cycle_candidate_filter` (`application.rs:3326`) cycles Neutral → Included → Disregarded → Neutral. `candidate_passes_dimension` (`:3292`) hides only **disregarded** matches. Included and Neutral remain visible. `visible_candidates` (`:3219`) applies source/range shortcuts and each dimension. | Browser now cycles the same three states. Green filled means included, outlined means neutral, and bold red means disregarded. Disregarded categories hide matching cards. |
| Candidate source actions | `CandidateFilterBody` (`app.slint:449–509`) has Include/Disregard for the currently selected source and Reset. The source action in `main.rs:8341` changes config and persists it. Reset in `main.rs:10906` reactivates available categories. | Browser Include/Disregard changes the temporary source filter only; Reset restores available categories. No source settings are written from the preview. |
| Candidate and preview switch | `select_candidate` (`application.rs:3205`) clears prior edit/upscale preview when choice changes. Windows artist blue/pink preview and pane radios are in `app.slint:2520–2560`; artist search in `main.rs:4797–4880`. | Browser blue and pink controls replace the selected component and rerender panes and Selected Artwork. It still lacks Windows source ranking, comparison image window, and MusicBrainz candidate workflow. |

| Function | Windows rule and event sequence | Browser state / remaining difference |

| Fitment | `CompactFitMenuRow` (`app.slint:977–1005`) currently maps 1×–8× from the far left. Pane and Selected Artwork pointer handlers are around `:2533–2554` and `:2733`. ## Sequence checks for each WebUI revision

1. Switch Artist → Album → Fallback. Verify only missing-ID albums appear in Fallback, and no old candidate or Selected Artwork preview leaks into a newly selected item.
2. Expand Media Filter. Confirm all seven statuses start enabled, toggle multiple categories, lock, switch views, unlock, then restore All. Compare artist, album, and fallback track counts with Windows once track rows exist.
3. Launch a candidate search. Confirm source cards report actual searched providers, positive-count filter categories become green, and cycling a category to Disregarded removes only matching candidates. Lock before another search and verify the filter state persists.
4. Select blue artist and pink banner candidates independently. Confirm pane radios choose independent editing, both radios show the package, and Themed Packaging gates combined edits.
5. Place fitment at center (1×), shrink left, expand right, wheel zoom, then drag within the round mask and banner. Confirm only pixels move; the circle and pane geometry stay fixed. Repeat after changing another enhancement slider.
6. Select an album, open Album Track Embedding, and confirm no job exists until EMBED Batch. This browser prototype can stop at preview; production embedding requires a separate write-enabled service and logging.

The isolated browser index is SQLite and read-only. The planned PostgreSQL deployment and its write endpoints remain separate work. Windows changes stay in source/local test builds until that revision is explicitly tested.
