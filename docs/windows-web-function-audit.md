# Windows ↔ WebUI function audit

Source baseline: `windows/src/application.rs`, `windows/src/main.rs`, `windows/ui/app.slint`, and `windows/src/range.rs`. Browser implementation: `python/web_preview.py`, `python/web_preview/index.html`, `app.js`, and `app.css`. This is a rule and event-sequence audit against the Windows 2.0.4 local-update worktree. The browser has one opt-in isolated write action for Artist COMP thumbnail repair; cover, Artist Art, blue COMP MusicBrainz review/embedding, and the Embed Batch queue remain previews.

## Windows runtime evidence and renderer recovery

The local MEDIAPC 2.0.4 log from October 28 (`[MEDIAPC]-Windows-ui-1793239012987-15412.debug.log`) showed Alan Jackson report clicks returning through the preparation error path, while Aerosmith reached report checking and completion. Artist Overview had deliberately left all fallback inventories lazy (`fallback_albums=0`); the report incorrectly treated its currently cached track subset as the complete Artist inventory. Opening one COMP hydrated only that album, which could produce a partial report. An explicit Artist COMP Report now opens before gathering, waits for in-flight appearance metadata, reads every matching missing-ID album inventory in the background, preserves completion records, and then verifies thumbnails. Empty and unavailable inventories remain visible with an explanation. Request/gathered/ready/rejected counts and errors are logged, and debug startup includes the exact build commit. An isolated regression covers sparse cached rows, a never-opened second COMP, reopening after processing, cancellation, and unchanged fixture audio.

## Sequence checks for each WebUI revision

1. Switch Artist → Album → Fallback. Verify only missing-ID albums appear in Fallback, and no old candidate or Selected Artwork preview leaks into a newly selected item.
2. Expand Media Filter. Confirm all seven statuses start enabled, toggle multiple categories, lock, switch views, unlock, then restore All. Compare artist, album, and fallback track counts with Windows once track rows exist.
3. Launch a candidate search. Confirm source cards report actual searched providers, positive-count filter categories become green, and cycling a category to Disregarded removes only matching candidates. Lock before another search and verify the filter state persists.
4. Select blue artist and pink banner candidates independently. Confirm pane radios choose independent editing, both radios show the package, and Themed Packaging gates combined edits.
5. Place fitment at center (1×), shrink left, expand right, wheel zoom, then drag within the round mask and banner. Confirm only pixels move; the circle and pane geometry stay fixed. Repeat after changing another enhancement slider.
6. Select an album, open Album Track Embedding, and confirm no job exists until EMBED Batch. This browser prototype can stop at preview; production embedding requires a separate write-enabled service and logging.
7. From Artist Overview and Albums view, select an album and press Upscale Preview. Confirm Find & Match Artwork remains active and Selected Artwork changes to Upscale Preview. When a missing-MBID album is available, open Fallback and confirm the logo background, single album card, report, and library track rows. Selected Artwork starts blank; selecting a track reads its embedded tag, while LAUNCH COMP advances pending tracks.

The isolated browser index is SQLite and read-only. Artist COMP thumbnail repair is the only optional write; it touches copied music files, backs up their original embedded images, and writes a separate action log. The planned PostgreSQL deployment and broader write endpoints remain separate work. Windows writes are real; browser presentation must not be used as evidence that cover, Artist Art, blue-track MusicBrainz review/embedding, or Embed Batch writes exist.
