# SPLINED WebGUI

The supported server interface runs in a browser. Python handles providers, image processing, library and tag writes; PostgreSQL stores the catalog, completion ledger, and persistent work queue. Windows remains a separate native Rust application with its own SQLite store.

## First run

Deploy the [WebGUI and PostgreSQL stack](../docker/README.md), then open `http://127.0.0.1:8080` on the server or its configured LAN address. On the first network visit, create the one WebGUI administrator with a username, password, password confirmation, and the deployment's `SPLINED_WEB_TOKEN`. The token authorizes enrollment and recovery but is never stored in PostgreSQL; later visits use the saved username and password. After an account exists, **Forgot password?** validates the existing deployment token, replaces only the WebGUI password hash, and invalidates active browser sessions. It does not change the token, PostgreSQL connection credentials, catalog, or artwork records. In **Settings**, select the music library path as seen by the server, Cache Directory, V/A / OST Artist Images Directory, output policy, and provider credentials. A blank V/A / OST path resolves to `<Cache Directory>/artist-art`; this is an image directory, not a separate database. Save Settings, then choose **Full Refresh Library Index** for the first publication. Start in `read` mode; change **mode** to `write` to enable artwork and tag writes.

On later launches WebGUI checks Album folders and filenames without opening every normal track. A header action reports separate added, changed, and removed counts and applies only that delta. Normal Albums require at most one representative-file check; changed COMP/Fallback Albums rebuild their complete track identity inventory during the explicit index update. **Settings → Full Refresh Library Index** remains available when the entire PostgreSQL catalog must be deliberately republished.

Settings uses the same task-based sections and shared Config v5 presentation contract as Windows. The workspace opens wide and can be resized from its lower-right edge; independent Boolean choices use left-aligned radio-style selectors. **Library & Files** identifies the PostgreSQL catalog size and persistent mounted paths without recursively walking network storage. **Enhancement** includes the OLED Chroma Wheel, renameable banner colors, album-frame colors, a live card preview, Default and Custom A–D adjustment presets, native-resolution preservation, the 100–800% enlargement ceiling, and resolution ranges. Those WebGUI interface choices are stored under `webgui_ui` in Config v5 so they survive browser changes and safe settings backup/restore. **Artwork Sources** presents graphical provider ordering before the saved source-policy controls; optional dimensions remain unset until entered. **Connections** edits and tests the five supported credential files inline. The future AISPLINED companion remains visibly optional and disabled by default. Blank secret fields retain their existing values; saved secrets are never sent back to the browser. Container deployments normally supply PostgreSQL credentials through environment variables, so the Advanced connection field is managed by the server.

## Artwork workflow

1. Select an artist or album. **LAUNCH** on an artist queues review of its selected eligible albums; in an album view it searches that album's configured sources. **Artist Art** opens portrait and banner search. **MusicBrainz** searches alternate releases and lets you choose which release's artwork to inspect.
2. Choose a candidate or **Upload Art**. In Enhancements, use Filters, Fitment, and Detailed to prepare the image. Wheel to zoom and drag to position artist artwork. Proposed component radios choose what is previewed and written. Both radios allow writing the portrait and banner together; Themed Packaging applies shared adjustments.
3. **WRITE Cover** saves the prepared cover. **WRITE Artist Art** saves the chosen components. Read mode disables these music writes. **Upscale Preview** uses conventional Lanczos enlargement toward Ideal, capped by **Max Upscale Percent**; it is not an AI reconstruction. Turn **Upscale Below Ideal** off to preserve actual source resolution. Writing remains explicit.
4. **EMBED Batch** saves the prepared album cover and stages a verified snapshot for track embedding. It keeps the current workspace open. The **Album Track Embedding** button gains muted purple text, outline, and background while unfinished work exists.
5. Open Album Track Embedding and choose **Start All Staged**. Progress and failures are persisted. Artwork choices requested by queued work appear in the main Candidate Artwork dock: select a card to preview it, then press its **Choose** button. The dialog is reserved for non-artwork decisions. **Pause After Album** pauses waiting albums while the current operation finishes; **Pause ALL Albums** requests a pause between atomic track writes. **Resume** retries paused or failed work. A server restart pauses interrupted work until explicitly resumed. Staged artwork survives browser and server restarts.

An album without a MusicBrainz Album ID uses the COMP workflow. Folder cover artwork is never automatically substituted for individual COMP track artwork. Fallback album cards may preview one recorded embedded track thumbnail; this is display-only and does not make the folder sidecar authoritative. Artist selection reads only the indexed COMP card summary; it does not rescan fallback albums or build a full report. **COMP Report** deliberately loads and verifies the focused artist's matching tracks across missing-ID albums. A catalog imported from an older build can perform a one-time catch-up for incomplete fallback track inventories when the report is requested; application logs report that count. Green means recorded artwork has a valid thumbnail; purple means recorded artwork needs repair; blue needs an artwork decision. **LAUNCH COMP** queues blue tracks; **EMBED Comp** queues the selected track for review. Use **Review queued work** to choose candidates and MusicBrainz releases with browser buttons. Authority fields can requery Artist, Release, and Recording IDs. **REPAIR COMP** repairs readable recorded thumbnails and preserves original embedded images in the cache.

Normal and COMP embedding write exact square JPEG thumbnails at `output.embedded_thumbnail_size` (default 1200). Audio container metadata and non-front artwork are preserved. Failed writes are reported; queued jobs do not report success merely because they were staged.

## Browsing and display

The workspace fills the browser width, including ultrawide monitors such as 3440×1440. Resize its panels with the pane splitters; the main workspace stays aligned with the full-width header. On desktop, overview buttons follow the bottom of the resized pane while its content scrolls above them. Artist, album, and fallback views retain their separate scroll positions when you return.

Artists, Albums, and Fallback remember separate scroll positions during the browser session. Returning to the same artist or album restores the overview position; expanded album grids retain expansion and scroll. Biographies collapse to five lines, with same-size themed more/less text at the end of the final visible line. Dark, Chalk, and Light persist in the browser. Browser extensions that force colors can override the selected theme.

Media Filter retains the existing selected-item counter behavior. Status toggles narrow the list; this change does not introduce album-total status counters. Candidate Filter controls result visibility. Locked filters remain in place across selections.

Navidrome supplies biography, similar artists, and top songs when available. If Navidrome has no matching Artist or biography, WebGUI confirms MusicBrainz identity and obtains biography text from Last.fm; that fallback profile is retained in PostgreSQL. Indexed songs are identified separately from ranked metadata. Artwork counts refer to actual embedded track images, not folder sidecars.

## Data, recovery, and deployment

PostgreSQL is authoritative for WebGUI catalog and jobs. There is no silent SQLite fallback, and the native `scan.sqlite_shared` switch is not a WebGUI setting. Settings can explicitly import a read-only SQLite snapshot into an empty PostgreSQL catalog; paths must match the server's library. The source is left unchanged. Windows and WebGUI do not open the same live database; simultaneous writers to the same music library should be avoided.

Back up PostgreSQL using a consistent database dump, plus the config, credential, cache/staged-artwork, and any external artist-art volumes. Track changes require a music-library backup for full recovery. Do not treat a SQLite snapshot or the image cache as a PostgreSQL backup.

**Settings → Backup & Recovery** can download or restore a secret-free current-settings JSON and download the shared settings presentation contract. Catalog Maintenance is grouped directly below Restore so full refresh and one-time SQLite import remain deliberate recovery-adjacent actions. Safe JSON includes the WebGUI palette and enhancement presets but excludes provider secrets and PostgreSQL contents. Artist sample writing is disabled by default and requires an explicit persistent directory when enabled. These files help compare deployments and prevent UI/default drift; neither replaces PostgreSQL, credential, cache, Artist Art, or music-library backups. **Processing & Logs** shows a bounded view of PostgreSQL WebGUI audit events; it never returns credential values.

Run one WebGUI application process per catalog. Loopback operation may omit an access token; network binding requires one. Use HTTPS through a reverse proxy for remote access. The service rejects cross-origin writes and requires a session request token for mutations.

The browser tab uses `/favicon.ico`. Help includes **Save SPLINED dashboard icon**, which downloads the separate 1024×1024 PNG at `/assets/splined-dashboard-icon.png` for dashboards and launchers.
